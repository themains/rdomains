# rdomains correctness and model audit

This is the preserved **baseline** audit. See [the repair record](2026-10-26-repairs.md) for subsequent code changes and validation.

Audited on October 26, 2026 against rdomains default branch `master` at `de4df7746ca8ac4c2e743bd9290d69f961f650a8`, rather than the older local checkout or CRAN tarball. Compared with piedomains default branch `main` at `33fe0e8e0cf90aa1916f46abdceb07d93d09a7bd` and its published 0.15.0 release. All 23 exported functions and the exported model object were reviewed. Targeted executions cover the findings below; this is not exhaustive testing of every argument combination.

The package passes its existing checks but has consequential classification and provenance defects. Updating the Python dependency alone does not fix the R bridge. No production code or model defaults were changed during this audit.

**Priority findings and reproductions**

1. **R preprocessing changes real model predictions.** `R/pie_cat.R:91` and `:157`, `R/extract_text.R:79`. Current Python defaults to trafilatura for main-content extraction. R first removes HTML structure, so Python cannot distinguish navigation from the article. A controlled page with shopping navigation and a news article produces 266 words through native Python extraction and 766 through R's flattened input. The same cached weights, domain, and scoring function return **news 0.767874** natively and **drugs 0.537566** through the R input path. This proves an implementation mismatch, not a population accuracy estimate. Proposed repair: preserve raw HTML/cache paths and delegate extraction to the supported Python pipeline; define explicitly how already-extracted `pages$text` is handled. Regression: compare native Python and R predictions for the same HTML, including navigation, entities, multilingual text, and duplicate URLs.

2. **The Claude default is unavailable.** `R/claude_cat.R:80`. Official provider retirement is sufficient evidence; no paid request is needed to establish it. Proposed repair: select an active model, verify its accepted parameters, and replace live-key-only response tests with deterministic request/response fixtures. Both LLM functions should describe their domain-name-only evidence accurately.

3. **Repeated domains overwrite earlier page text.** `R/pie_cat.R:156`. Temporary files are named only by domain. Two rows for `example.com`, one about news and one about football, both classify as sports because the second file replaces the first before scoring. This is a realistic case for different paths on a host or repeated historical snapshots. Reproduced through the actual Python file-reading path with a deterministic scorer. Proposed repair: unique filenames per row; retain domain separately as a model feature. Test row-order reversal and same-domain distinct-page inputs.

4. **Inference failure is counted as success.** `R/pie_cat.R:98` and `:180`. Python refuses a short-text row with `thin_content`; R discards its error information, returns `status='ok'`, `stage='process'`, `pie_category=NA`, and `label_source='model'`. `fetch_report()` then reports one success and zero failures. Backend-unavailable returns also retain successful fetch status. Proposed repair: preserve inference outcomes and update the row's status/stage/error fields; do not assign a model label source when inference failed. Keep successful fetch provenance separately.

5. **The advertised threshold is ignored.** `R/pie_cat.R:139`. With returned probabilities news 0.6 and shopping 0.4, `threshold=0.1` and `threshold=0.9` both return both labels. `NA` is also silently accepted. The argument is neither applied nor passed to Python configuration. Proposed repair: validate a finite scalar in [0,1] and implement the documented filtering, retaining the argmax. The current documentation says filtering applies to Python's already-returned labels; changing it to the complete probability distribution is a separate contract decision.

6. **Model provenance is wrong.** `R/pie_cat.R:198` always reports `soodoku/piedomains-text`, even when the real loaded checkpoint is `gojiberries/piedomains-text` or an override. Confirmed during actual local inference. Proposed repair: report resolved checkpoint, revision, package version, extraction settings, and calibration metadata rather than a literal name.

7. **The URL cache aliases distinct pages.** `R/page_cache.R:59` lowercases the entire URL. Writing `/News` and reading `/news` returns the first page. Paths and query values can be case-sensitive. Proposed repair: normalize only scheme and host, preserving the resource portion; test both path and query case and continue checking host-case equivalence.

8. **robots.txt enforcement checks the wrong path.** `R/collect_content.R:380` always asks about `/`, including when a URL contains a path. A real local server declaring `Disallow: /private` is fetched at `/private` and through a redirect from `/start`; both results report `status='ok'` and `robots_allowed=TRUE`. Redirect destinations are address-checked but their robots rules are not evaluated. Separately, `robots_for_origin()` lets the HTTP client follow redirects without the content path's address validation; a local robots redirect was followed to completion. No real private service was contacted. Proposed repair: check actual path/origin at every hop and use guarded redirects for robots fetching too. Reference: [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html).

9. **Source dates can claim freshness that the source does not have.** `get_ut1_data()` takes the newly downloaded temporary file's local modification time and calls it the list publication date. A fixture containing a 2020 source file was reported as published on October 26, 2026. `stevenblack_cat()` likewise uses local file modification time. `dmoz_cat()` returns 2017-03 even though the documented bundled snapshot is from 2015; 2017 is the service closure, not this snapshot's date. Proposed repair: distinguish fetched-at, local-file mtime, and verified source publication dates; preserve provenance in explicit metadata instead of relying on filesystem dates.

10. **Custom category vocabularies are not enforced.** Both LLM helpers return literal `other` for unrecognized output even if the caller supplied only `news` and `sports`. Reproduced with a realistic successful OpenAI response fixture. Proposed repair: treat out-of-schema output as classification failure, or allow a fallback only when it belongs to the supplied vocabulary. Validate categories and rate-limit/model parameters before sending a request.

11. **An explicit VirusTotal key can be ignored.** `R/virustotal_cat.R:26` uses `apikey` only if `VirustotalToken` is empty. With an existing environment value, an explicitly supplied replacement is not applied. Reproduced using non-secret fixture strings and a mocked vendor response. Proposed repair: explicit argument takes precedence without unexpectedly changing unrelated session credentials. The installed VirusTotal client itself handles URL stripping; lack of stripping in this wrapper alone was not reported as a defect. Reference: [VirusTotal domain endpoint](https://docs.virustotal.com/reference/domain-info).

12. **Ordinary URL variants miss existing lookup records.** Shared `clean_domains()` removes scheme and slash suffixes but leaves query strings, fragments, and ports when they follow the host directly. A Shallalist fixture matches `example.com` but returns missing categories for `https://example.com?x=1`, `https://example.com#news`, and `https://example.com:443/`. Proposed repair: parse the hostname with a maintained URL parser, preserving the original requested URL for collection/cache purposes. Apply consistently to sibling lookups.

13. **The archive adapter has boundary and time-selection problems.** A header-only CDX response is interpreted as a capture and produces `https://web.archive.org/web/timestampid_/original`. Verified with an HTTP response fixture. With a target date, the implementation requests the first capture at or after that date, despite describing it internally as closest and publicly as historical/as-of content. The empty-response bug should be fixed directly. The historical selection contract needs an explicit choice: at-or-before versus nearest, with the realized timestamp always preserved. External archive availability and a full historical-capture test were not established in this audit.

**Model quality and evaluation roles**

The published model card reports 0.818 accuracy and 0.758 macro-F1 on 4,382 held-out documents. Its domain hash determines train/validation/test membership. Checkpoint metadata says the temperature was fitted on validation data, with reported ECE improving from 0.04899 to 0.01684. Those are publisher-reported results, not a fresh independent evaluation on October traffic.

The same card documents contaminated `drugs` training labels and retail misclassification, and weak classes including `urlshortener`, `library`, `socialnet`, and `shopping`. Updating a package version does not relabel those training observations. Reporting multiple softmax alternatives also does not establish that all returned labels are correct: the evaluation gold is single-label. Before claiming improved accuracy, compare the repaired bridge with native Python on a fixed HTML corpus, then evaluate both on independently labeled, temporally relevant domains. Report class-wise precision/recall, macro-F1, calibration, coverage/abstention, and failure rates; do not score only successfully classified pages without reporting exclusions.

The old adult model's training date and contemporary calibration are not recorded in its runtime output. Its feature loops include fixed positions 1:60, an unescaped-dot numeric-host regex, and suffix substring matching. These deserve comparison with the original training feature builder before changing them: changing inference-only features could break training parity. They are audit leads, not newly confirmed model-quality fixes.

**API vocabulary and constants**

Most lookups accept `domains` and return `domain_name`. Steven Black instead accepts `domain` and returns original `domain`; VirusTotal returns `domain` and uses `apikey` rather than the LLM functions' `api_key`; `not_news` intentionally accepts URLs and returns URL flags. Lookup schemas do not share the collection/inference outcome schema. Standardizing names and return types is an API decision, not a hidden compatibility shim.

Priority numeric boundaries are `pie_cat(threshold)` in [0,1]; nonnegative finite inter-request delays; positive timeouts and byte limits; integer nonnegative redirect counts; valid cache TTL/size; scalar flags; valid archive dates; and complete `pages` column types. Confirmed failures include ignored/NA thresholds and missing `page_state` silently producing no classifications. Exhaustive combinations of all crawler parameters were not run. The R 8,000-character cutoff is an unverified proxy for the Python 256-token window and should not substitute for tokenizer-controlled truncation.

**Validation and retained evidence**

- `devtools::test()` through the package harness passed with paid API keys unset and `NOT_CRAN=false`: 18 expected skips cover live services and external downloads. Local HTTP-server tests ran outside the filesystem sandbox because the sandbox cannot bind loopback sockets.
- `lintr::lint_package()` reported zero lints.
- `devtools::check()` completed with **0 errors, 0 warnings, 0 notes**, including install/load checks, examples, tests and vignette rebuilding. Paid API keys were unset in the check subprocess.
- Installed the latest piedomains source with its frozen runtime lock in a temporary Python environment. Loaded the actual cached pinned weights, tokenizer, labels and calibration, then ran real inference locally on CPU. No new model training or broad accuracy benchmark was run.
- Deterministic Python scorer probes exercise the actual bridge/file/extraction path for threshold, duplicate-row, and failure handling. Separate real-weight probes establish that inference loads and that extraction differences change predictions.
- HTTP mocks isolate UT1 provenance, LLM schema handling, explicit VirusTotal key precedence and empty-CDX behavior. Real local HTTP servers establish robots-path behavior.
- An initial sandbox test attempt failed on socket binding and had unsuccessful network-dependent OpenAI tests; it was not counted as a package defect. The clean rerun explicitly removed API credentials. No successful paid classification was used as evidence.

The `evidence/` directory retains R/Python reproductions, their outputs, the extraction fixture, the model card, lint output, local-test output and full R CMD check output. Reproduction scripts reference `/tmp/rdomains-audit-20261026` and `/tmp/piedomains-audit-20261026`; retain these audit environments or adjust the paths before rerunning. The original rdomains checkout and advertiser repository remain untouched.

Recommended implementation order: first correct the bridge's input, row identity and outcome/provenance handling; then repair cache and robots behavior; then migrate provider defaults with fixture tests and a small authorized quality evaluation; finally repair source metadata and refresh the model's contaminated labels. Release only after rerunning the existing checks and the new regression suite. This audit records defects and proposed contracts; it does not claim those repairs have been implemented.
