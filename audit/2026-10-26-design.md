# rdomains: remaining work and design audit

Audited October 26, 2026 (Pacific), against default branch `master` at `1bad0007a09f30e42709d04aa8141e05eb3cfbec`, after PR #16. The source tree was clean. This audit changes no production code and makes no paid API calls.

**Assessment.** The earlier repairs materially improved the collection/inference path, but the package still needs correctness work and a coherent user-facing contract. It currently combines current-page inference, historical lookups, blocklist membership, university ownership, domain-name inference, and old regex/model heuristics under similar names. These are useful capabilities, but they answer different questions. A common result envelope should make those differences explicit rather than pretend their taxonomies or probabilities are interchangeable.

“Hadley-style” below means an application of published tidyverse design principles, not an attribution of these recommendations to Hadley Wickham. The criteria are [composability and consistency](https://design.tidyverse.org/unifying.html), [type stability](https://design.tidyverse.org/out-type-stability.html), [shared result constructors](https://design.tidyverse.org/out-multi.html), and [structured conditions](https://design.tidyverse.org/err-constructor.html).

**Evidence and limits.** Reviewed all 23 public callable implementations, their signatures and output contracts, plus exported `glm_shalla`. Ran 15 targeted behavior/contract probes and generated the public signature inventory. Re-ran the package harness with provider keys unset, `NOT_CRAN=false`, and the installed piedomains 0.15.0 test environment: **480 assertions passed, 18 expected skips, zero failures/warnings; lint reported zero findings**. The Python integration test ran; it substitutes the scorer, so this fresh run is not a new accuracy evaluation. Earlier real-weight parity evidence remains in the prior audit. This is not an exhaustive boundary matrix, live-provider evaluation, or population estimate of defect frequency.

Reproduce with `Rscript audit/evidence/design-audit-probes.R`. The script loads the normal checkout at `/Users/soodoku/Documents/GitHub/themains/rdomains`; adjust that path on another machine. HTTP/provider results are deterministic fixtures. Outputs are in `audit/evidence/design-audit-probes.log`; the full baseline is in `audit/evidence/design-audit-tests.log`.

**Confirmed behavioral findings**

| Priority | Finding and evidence | Consequence | Proposed repair and acceptance test |
| --- | --- | --- | --- |
| P1 | `R/page_signals.R:209` treats any occurrence of a named parking marketplace as conclusive, before the length guard. A 308-word news-style fixture mentioning `sedo.com` returns `parked`. `pie_cat()` then returns `status=ok`, `pie_category=parked`, `label_source=heuristic` without calling the model. | A substantive page can receive a false terminal label. | Require corroborating placeholder evidence. Test real parking templates alongside long articles discussing parking companies and registrars. Preserve a separate page-state field. |
| P1 | `R/collect_content.R:341` sends the cleaned hostname to `archive_fetch()`. Input `https://example.com/News/story?id=7` becomes `example.com`. The fallback path does the same. | Historical collection changes the requested resource, potentially classifying a homepage in place of an article. | Carry the original URL through archive lookup and recovery. Assert exact path/query preservation, including two distinct pages on one domain. If only homepage archives are intended, reject unsupported URLs explicitly. |
| P1 | `R/page_cache.R:81` validates the cached timestamp but not the rest of the metadata schema. A valid JSON sidecar with `http_status=[200,201]` causes collection to error with a scalar-coercion failure before returning the batch. | One damaged cache record violates the promise to retain every requested row. | Validate the full cached record and treat invalid records as misses. Test missing fields, wrong scalar types, invalid enums and a healthy second batch row. |
| P1 | `R/archive.R:35` collapses non-200 responses and parsing/transport failures to `NULL`. A fixture HTTP 503 and an HTTP 200 with no captures both become `no_archive_snapshot`, `retryable=FALSE`. | An archive outage is reported as evidence that no capture exists. | Return structured archive outcomes. Distinguish no capture, rate limiting, timeout, invalid response and service failure; preserve the underlying status. |
| P1 | A robots request timeout becomes `rules=FALSE`; collection returns `robots_blocked`, `retryable=FALSE`, with no HTTP status. The result is cached with the default 24-hour robots TTL. | Temporary inability to read robots rules becomes indistinguishable from explicit disallow. | Keep refusing the fetch while rules are unknown, but preserve the transient reason and use a separate failure-cache policy. Test timeout/503 versus an actual `Disallow`. |
| P2 | A fixture HTTP 404 returns `http_error`, `retryable=TRUE`; retryability is determined by the generic code alone (`R/outcomes.R:29`). | “Retry only worthwhile rows” includes ordinary not-found responses. | Derive retry advice from status/reason and distinguish repeat-now from intervention-required. Test 404/410 against 429/503. |
| P2 | HTTP 302 with a substantial HTML body and no Location returns `status=ok`, despite the error vocabulary describing non-2xx responses as errors (`R/collect_content.R:433`). | An unresolved redirect response may be classified as a successfully fetched page. | Define terminal HTTP success explicitly; test missing/blank Location with both empty and substantive bodies. |

The first parking probe is a constructed counterexample, not a claim about the prevalence of this error on the live web. The corrupted-cache case is robustness against an invalid cache record, not a claim that normal cache writes routinely produce arrays.

**Hadley-style API audit**

| Design criterion | Current behavior | Recommended contract |
| --- | --- | --- |
| Predictable outputs | `virustotal_cat()` returns different columns depending on which vendors reply. A fixture produces `domain_name, VendorA` for one domain and only `domain_name` for another. LLM wrappers return only a domain and provider-specific category. | A stable common result core, with typed label/detail tables for variable vendor output. Unknown scores stay missing rather than becoming invented probabilities. |
| Consistent failure semantics | Collection has `status/stage/error_code/retryable`; LLM HTTP 429 is reduced to `NA` plus a warning. Missing lookup membership, provider failure and malformed output cannot be handled uniformly. | Preserve machine-readable outcomes and relevant HTTP/model provenance across adapters. Keep no match distinct from failed execution. |
| Composable vector operations | Most domain functions reject `character()`. The documented retry expression therefore errors when no rows need retrying. `pie_cat()` already accepts a zero-row page table. | Return typed zero-row results for empty vectors. Continue rejecting malformed nonempty inputs. |
| Composable side effects | `get_dmoz_data()` successfully writes its file but returns `NULL`; the other three downloaders return an invisible path. | Every downloader returns the written path invisibly and uses the same directory/overwrite rules. Add a download-then-lookup composition test. |
| Preserve identity | Collection retains original `input`; most other classifiers keep only normalized `domain_name`. The retry example uses `res$domain_name`, dropping paths, query strings and the original scheme. | Preserve an input identifier and original input in every adapter. Retry original inputs with the same acquisition options. Test duplicate domains with different URLs. |
| Explicit arguments and state | Required domain arguments default to `NULL`; model selection relies partly on Python environment/configuration; list functions differ between implicit downloads and files in the working directory. `collect_content()` has 15 arguments. | Required inputs should be required. Make source/model selection and persistent state inspectable. Group acquisition controls only if it demonstrably simplifies real calls; do not add an options framework for its own sake. |
| Appropriate names | `not_news()` returns independent soft/hard keyword flags, not a reliable news/non-news decision. `adult_ml1_cat()` returns a probability from a 2017 artifact. `rate_limit` means sleep seconds, unlike collection's `delay`. | Name functions and fields by what they measure; use one vocabulary for delay units. Make any renaming one deliberate breaking release with migration examples. |
| Useful errors | Boundary errors mix `stop()`, checkmate and cli; per-row errors are often flattened into warning text. | Use a small condition hierarchy for caller errors and structured row failures for operational errors, pointing to the public call. |

A workable result core would preserve `input_id`, `input`, `domain_name`, `provider`, `evidence_type`, terminal outcome fields, and typed label/provenance details. Keep the label provider distinct from content origin (`live`, `cache`, `archive`). Keep source-native taxonomies and vendor labels intact. Collection payloads can remain separate from classification results; there is no need for a universal 60-column table or a new class hierarchy.

**Jobs-to-be-done audit**

These jobs are inferred from the documented features and your research workflow; they are not findings from user interviews.

| When I need to… | What currently obstructs the job | Definition of done |
| --- | --- | --- |
| Classify what a website contains now | Automatic archive fallback permits old content; page-state false positives can bypass inference; checkpoint quality remains unvalidated for current use. | A clearly selected current-content policy, transparent abstention, reliable page-state handling, and measured coverage plus label quality. |
| Classify a page as of a historical date | Archive lookup loses page identity and cannot distinguish outage from absence. | Exact-resource capture lookup, realized timestamp, structured acquisition failures, and saved evidence sufficient to reproduce the result. |
| Process a large URL table and resume after interruption | No uniform input key, partial-result/checkpoint interface, empty-batch behavior or retry contract across providers. | Persistable results keyed to original inputs; examples that resume only failed work without repeating successful paid calls. Establish a representative batch benchmark before introducing concurrency. |
| Compare what several sources say | Different schemas and taxonomies; ambiguous `NA`; UT1 drops extra memberships using category size as a proxy for specificity. | Bindable results with provider, evidence type and taxonomy; retain multiple memberships or make reduction an explicit policy. No claim that smaller categories are semantically more specific without evidence. |
| Defend a result in research | API inference omits returned model identity/request provenance; university data is downloaded anew and lacks file/provenance controls; recent human evaluation is absent. | Stable inputs/artifact identifiers, dates and model metadata; a separate evaluation report with clearly independent labels. |
| Install and run the core workflow | Python environment discovery, optional dependency installation and a first model download are separate failure points. CI skips the Python bridge unless an environment variable is supplied. | A tested fresh-environment setup path, an offline cached-model path, and a dedicated Python integration CI job. |
| Know which function answers my question | The reference is alphabetical and mixes content inference, memberships and historical heuristics. | Task-based guides for current content, historical content, memberships, name-only inference and reproducible batch work; retain automated reference completeness checks. |

The package should not silently substitute name-only guesses or archived pages when the job requires current page evidence. These may be useful explicit alternatives with their own provenance.

**DRY audit: share knowledge where drift matters**

1. **Outcome contract and page-policy constants across R/Python.** Both packages copy outcome names, retry semantics and heuristics. The compared Python version contains `archive_rate_limited`, which R lacks. Python treats `bot_blocked` as retryable; R does not. The difference is explicitly tested, but the R test's rationale says R has no archive fallback, which is now false. Different capabilities can justify different policies; the missing piece is a versioned shared contract, documented exceptions and parity fixtures. Avoid requiring Python just to use R-only lookups.
2. **OpenAI/Claude orchestration.** Default categories, normalization, key resolution, iteration, delays and result construction repeat. Prompt generation and option validation are already shared. Extract a common batch/result layer and one category definition. Keep provider-specific request bodies, authentication and response parsing separate.
3. **Downloader lifecycle.** Directory checks, overwrite decisions, temporary-file cleanup, messages and path returns repeat and have already diverged. Share that small lifecycle; keep ZIP, gzip, tar and hosts parsing separate. Extend the existing `download_source()`/metadata helpers rather than inventing a framework.
4. **Archive/live/cache postprocessing.** `fetch_one()` repeats HTML extraction, signals, outcome decisions and result population across live, cached, explicit-archive and fallback paths. Factor classification of an acquired page into one pure helper, with acquisition provenance supplied explicitly. Use equivalence tests across live, cached and archived copies of the same fixture.
5. **Metadata policy.** Snapshot dates appear both in downloader code and `SOURCE_VINTAGE`. URLs and source identities also repeat. A small source registry can own these facts while generated docs use the same definitions.
6. **Low-value leftovers.** `is_thin()` duplicates token-count logic and is unused by production code; the 30-word cutoff appears separately in `page_signals()`. `XML`/`readHTMLTable` are still imported although no production call remains. Remove verified dead code/imports; reassess compulsory legacy-model dependencies separately.

Do not deduplicate the R visible-text extractor and Python model extractor into one algorithm: they now serve different purposes, and the earlier repair correctly restored Python preprocessing. Do not collapse all source categories into one vocabulary merely to make tables bindable.

**Other remaining risks**

- **Lookup ambiguity:** a custom Shallalist CSV with two categories for one domain returns the first match. Reversing rows changes `news` to `shopping`. Define duplicate-key behavior and validate file schemas/types; either retain memberships or reject an ambiguous single-label source. Current validation checks required column names only.
- **Model validity:** the 44-label mmBERT checkpoint still has documented drugs/retail contamination. The saved training-only cleanup candidate removes 259 rows while preserving validation/test and all 44 labels; it is not independently adjudicated or trained. Evaluate recent held-out data, acquisition coverage, classwise quality, calibration and abstention before publishing new weights. The adult model also lacks current validation; do not change its feature encoding without the training oracle.
- **Release:** GitHub development code and docs are updated, but the version is still `0.5.0.9000`; no new CRAN release was made. API changes need a declared release boundary and migration notes.
- **Integration coverage:** ordinary CI does not provision piedomains or set `RDOMAINS_TEST_PYTHON`. The explicit skip means the core cross-language path can regress while the R matrix stays green. Add deterministic bridge tests in CI and a separate pinned-weight parity check; neither needs paid API calls.
- **Performance:** `stevenblack_cat()` performs membership lookup inside a per-input loop and reparses the hosts file on every call. A synthetic 100,000-host/1,000-input fixture matched the expected membership exactly. Timings are recorded in `audit/evidence/design-audit-performance.log`; the comparison excludes work from the vectorized expression and is not an end-to-end speedup estimate. Profile representative workloads before optimizing. `pie_backend()` constructs a classifier each call; repeated-small-batch cost also needs measurement.
- **Dependency floor:** CI covers current release, devel and oldrel-1, while DESCRIPTION promises R >=4.1.0. That does not establish the declared minimum works with the dependency stack. Add a floor-version check or revise the support declaration based on tested requirements.

**Recommended execution order**

1. **Correctness patch:** parking false positives, exact archive URL identity, archive/robots failure distinctions, cache-schema validation and terminal HTTP handling. Each gets a failing regression, a verified fix, a reversal check and full-suite verification.
2. **Result contract:** stable provider results, original input identifiers, typed empty results, explicit no-match semantics, reusable downloader paths and unambiguous lookup memberships. Agree the new contract once, then migrate the package without compatibility aliases.
3. **Focused consolidation:** common LLM batch/result logic, downloader lifecycle and pure acquired-page postprocessing. Consolidate only after the required behavior is fixed in tests.
4. **Continuous verification and usability:** Python integration CI, minimum-R validation, fresh/offline setup checks, task-based documentation and representative batch profiling.
5. **Model and release work:** independent evaluation and justified retraining, followed by reviewed versioned publication. Do not make a code-quality cleanup stand in for evidence of model quality.

The immediate next step is item 1. Cosmetic renaming or a universal classifier wrapper should not precede the reproduced behavioral repairs.
