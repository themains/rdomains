# rdomains audit repairs, October 26, 2026

Branch: `fix/audit-20261026`, based on current default-branch commit `de4df77`.
The [baseline audit](2026-10-26.md) records the defects before these changes.

## Completed code changes

1. Preserve raw HTML for piedomains extraction. Use unique temporary files for every
   input row, including repeated domains. Require piedomains >=0.15.0 and validate the
   supplied page schema. Apply thresholds to the full probability distribution.
2. Preserve collection outcomes in `fetch_*` columns. Report failed inference as a failed
   terminal outcome, distinguish loading from prediction errors, and expose the actual
   model repository, revision, package version, extractor, cleaning and temperature.
3. Parse URL hostnames while preserving the original requested resource. Keep path and
   query case in cache keys; use a new cache namespace. Include metadata in cache budgets.
4. Enforce robots rules for the requested path and each content redirect. Apply address
   guards to robots redirects, cap downloads, and validate crawler numeric boundaries.
5. Reject empty/malformed CDX results; historical collection means the most recent capture
   at or before the requested date. Preserve realized capture time and raw HTML.
6. Update provider defaults to `gpt-6-luna` and `claude-haiku-5-5`, using their documented
   token and sampling parameters. Reject truncated and out-of-vocabulary replies. Require
   an explicit opt-in before tests can use paid provider credentials.
7. Respect explicit VirusTotal credentials and restore the surrounding environment.
   Standardize its key argument to `api_key` and its output to `domain_name`; Steven Black
   now accepts `domains` and returns normalized `domain_name` too.
8. Record publication and retrieval dates separately in checksum-bound metadata. Ignore
   stale, corrupt or missing sidecars. Correct the DMOZ snapshot to 2015, retain the
   Shallalist snapshot date, and return `not_listed` for hosts absent from Steven Black.
9. Document the 2017 adult model and the piedomains checkpoint's known label contamination.
   Remove unsupported current-accuracy claims and stale sample outputs from usage docs.

## Model state and remaining work

The current Python library is 0.15.0, but its default model weights remain the August 1
checkpoint `gojiberries/piedomains-text` at
`38d7e6403f911902f47b9218ce5c645a06dd02fe`: fine-tuned `jhu-clsp/mmBERT-base`,
44 classes, calibration temperature 1.248333215713501. No weights were retrained here.

The model card documents retail/drugs confusion. Existing piedomains reports already
contain an 828-document drugs relabeling audit, a 200-document sports control audit and
a stratified human-review sheet. Those LLM labels explicitly are not evaluation gold.
Reuse and review that work before paying to label it again.

The next model-quality phase is:

1. Locate the prepared corpus and verdict cache; verify domain-hash train/validation/test
   separation and preserve independent human evaluation labels.
2. Review the existing drugs audit and its abstentions. Define the drug/pharmacy/tobacco
   taxonomy explicitly and verify quoted evidence against saved page content.
3. Evaluate the current checkpoint on a fixed, independently labeled recent corpus,
   including retail and weak classes. Report acquisition failures and coverage alongside
   per-class precision/recall, macro-F1 and calibration.
4. Only after the spending limit is set, run any missing labeling pilot and retraining.
   Compare on the unchanged held-out corpus, recalibrate on validation data, and publish
   a new checkpoint only after evidence supports improvement.

No paid calls, model publication, CRAN submission or GitHub release occurred in this
repair pass. Provider request contracts were tested with fixtures; live provider behavior
and classification quality were not measured. The broader development check also ran its external-download and public-site tests
successfully; this is a point-in-time result, not an availability guarantee. The crawler's
